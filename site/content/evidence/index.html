How to read these pages

Each experiment page separates five things that a summary would merge: what the experiment found, what it refuted — including its own predictions — what went wrong during it, what its numbers are, and what a reader must not conclude from any of it.

Every metric card carries four things beyond its value: what it measures, how it was collected, what it does not show, and a link to the artifact. Following that link is the point of the exercise.

How each number was produced

Instrumented

A machine recorded it

A test runner, a build wrapper, a git count, a platform usage API. The most reliable class here, and still only as good as what the instrument was pointed at.

Self-reported

The agent recorded its own work

Search counts, discovery classifications, mistake counts. In the paired trial every self-reported build and test result was independently re-verified against committed diffs, with zero discrepancies — but self-classification standards differed between agents, which is why two of those figures are not comparable to each other.

Derived

Computed from other values

Structural counts from regex rules, ratios between recorded figures. The counting rule is stored with the number, because the rule is a judgement.

Not observable

The telemetry never existed

An absence of data, not a zero. Several experiments here have no token or cost figures at all, because the runtime exposed none to the running agent. They are labelled rather than omitted.

What this evidence base cannot support

  • Any general claim about the industry. {{count:experiments}} experiments in one organisation, mostly by agents from one model family. That is not a sample of software engineering.
  • Any percentage improvement you could put in a proposal. No experiment here was designed to establish an effect size, and the one that came closest has incomplete telemetry for its treatment condition.
  • Portability beyond F#, TypeScript, C# and JavaScript. Nothing here touches any other ecosystem.
  • Anything about teams. Every experiment was executed by a single agent or a single supervised session.
  • A comparison against unconstrained development. No experiment here has a counterfactual arm in which the same requirements were built without the method.
