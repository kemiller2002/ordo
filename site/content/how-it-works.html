How it works

How Ordo works

Ordo is an order of operations and a set of structural commitments, not a framework to install. Below, each mechanism is paired with the consequence it produces and with what was actually observed — because a mechanism with no consequence is decoration, and a consequence with no measurement is a hope.

The construction order

{{diagram:engineering}}

Verification is not a phase at the end. It is several mechanisms with different sensitivities, applied in order of how early and how cheaply each can refuse a mistake.

Status: the individual steps are separately supported; the ordering has not been trial-tested as a single workflow on a production project.

Explicit state

Mechanism

The state is stored, not derived

A record is in a named state from a closed set. Fields meaningful only in one state are constructible only in that state. Exhaustiveness checking is a build error.

Consequence

Nothing has to decode a combination

No read site combines flags to work out what is true, so no read site can combine them differently. Adding a state produces a failing build at every place that must now decide what it means.

Observed

Three states, four transitions, twenty-four refusals

The measured build declares {{metric:M-GF1-TRANSITIONS}} and {{metric:M-GF1-DIAGNOSTICS}} — each refusal a named value rather than a thrown exception or a null.

Guaranteed, not measured: in the C# state implementation, TimeOfDay and DurationMinutes are distinct nominal types specifically so a duration cannot be supplied where a time-of-day is expected. That is a property of the source, readable in the source.

Legal transitions

Mechanism

Change goes through declared routes

Transition functions are the only thing that constructs a new state value. Terminal states are enforced by every guard and asserted by tests, not merely absent from the code.

Consequence

Illegal actions are unavailable, not rejected

An agent choosing from the legal set cannot construct an illegal request. Constraint replaces remembering: the action space shrinks instead of the rulebook growing.

Observed

Independent builds agreed

Two agents with no contact produced identical state machines and transition sets from the same requirements, differing on {{metric:M-GF2B-SCOPE}} across 41 requirement-level decisions — and that one was a scope question, not a rule.

One authority per rule

Mechanism

Capabilities are derived, never copied

What an actor may do next is computed by calling the same named predicates the transitions use as preconditions.

Consequence

Two answers cannot disagree

The interface and the enforcement cannot drift apart, because there is one of them. A change to the rule changes both by construction.

Observed

Reached independently, and proved

Both greenfield builds arrived at this architecture separately and documented the reason in nearly the same words. One proved the sharing was real by deliberately breaking the shared predicate and confirming both callers broke together.

Structural locality and deterministic routing

Mechanism

Route, do not explore

A repository map points from semantic areas to locations; a feature's owned state, behaviour, contracts and tests stay bounded together. Navigation artifacts declare by reference and never restate a rule.

Consequence

Less has to be read to change anything

Finding where a decision lives becomes routing rather than search — which matters most for whoever arrives without the model already in their head.

Observed

Eighteen searches, no expansions

{{metric:M-TE-CSSTATE-SEARCH}} across a whole trial, with {{metric:M-TE-CSSTATE-CONTEXT}} occasions where context proved insufficient. Separately, {{metric:M-TE-CSSTATE-COLDSTART}} cold-start questions were answerable without opening a source file.

Honest about this one. The search figure comes from an agent working against a specification it had just written — a favourable condition, and not a measured reduction against a baseline. {{ref:R-RESUMPTION}} supports the general idea that contextual reconstruction aids help, and {{ref:R-EXPERTISE-REVERSAL}} is the reason to expect they cost something for an expert who already holds the model.

Boundary authority

Mechanism

One authority, a derivation, or a check

A fact crossing a boundary has a single source, something derived from it, or a mechanical agreement check between the copies. Unknown outcomes are a distinct state, not a collapsed success or failure.

Consequence

Silent divergence needs a mechanism to stay silent

Adding a case to a closed set stops producing a compiler error at one site and silence at the others.

Observed

Discovery went from two-thirds to complete

{{metric:M-HN1-MDR}} required sites were machine-reported before hardening; {{metric:M-HN2-MDR}} after five targeted mechanisms. One mechanism removed a site outright rather than mechanising its discovery.

And what it did not do. {{metric:M-HN2-BCA}} — boundary work per semantic decision did not change, measured three times across two architectures. Hardening changed how required work was found, not how much there was. Anyone claiming otherwise is contradicted by our own measurements.

Verification that fails differently

Mechanism

Mechanisms chosen for differing blind spots

Types, architecture checks, contract checks, behavioural tests, integration against a real boundary, and independent adversarial review — not more of whichever one you already have.

Consequence

A green suite stops being the only signal

Which matters because a green suite has been independently measured not to establish merge-readiness.

Observed

Zero overlap

{{metric:M-GF2B-OVERLAP}} of an independent reviewer's findings were already covered by a 90-test suite plus a mutation-tested adversarial self-review. In another build the suite itself {{metric:M-GF2A-DEFECTS}}.

Evidence as an output

Mechanism

Record what ran and what was never captured

Every metric carries a definition, a collection method and a statement of what it does not show. Telemetry that does not exist is labelled, never estimated.

Consequence

A later reader can tell what was established

Including when the answer is "nothing" — which is the case for several figures on this site, and they say so.

Observed

Applied to this site

A metric with no stated limitation or no resolvable source cannot be represented in this site's own evidence manifest. The build fails rather than rendering it.

What this costs

Ordo adds explicit types, transition definitions, a semantic map and architectural checks. That is real work, done once, before the thing it protects exists. It is recovered — where it is recovered — in defensive branching that no longer has to be written, rules that exist in one place instead of several, and change surfaces that are reported rather than discovered.

Whether that trade is net positive over a codebase's life is not something we have measured. No change-task trial has been run against a state-structured build, so the compounding argument has no data behind it. We think it is likely. We are not claiming it.
