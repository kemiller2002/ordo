How it works

How Ordo works

Ordo moves decision-relevant meaning out of convention and into explicit domain structures. The method asks a simple sequence of questions: what can be true, what do we actually know, what authority exists, what legal change is available, what happened at the boundary, and what remains unresolved?

The loop

A safe decision is constructed before it is selected.

The provider, model, or engineer operates inside a domain-defined choice space. It does not define that choice space.

State

Project the smallest semantically complete state view

The domain selects the authoritative facts that could change the legal outcome. The view carries a schema/version identity and Ordo fingerprints the whole selected view.

Knowledge

Attach evidence and scoped coverage

Evidence carries provenance. Coverage states whether a named scope is Complete, Partial, or Unknown. Required incomplete coverage stops the decision before provider execution.

Authority

Resolve capabilities, obligations, and policy

Capabilities represent host-established semantic authority. Obligations represent work that must still be satisfied. Policy and transition guards determine what is actually legal.

Decision

Choose only among legal alternatives

Deterministic computation is preferred where practical. A bounded model decision can be used where judgment is required. Missing prerequisites produce refusal or escalation, not a fabricated answer.

Effect

Request external work as data

Tier Two requests the effect. Tier Three coordinates the boundary. Tier Four performs or observes the external work.

Reconcile

Interpret Succeeded, Failed, or Unknown

Unknown is preserved as Unknown. State-changing unknown effects create a reconciliation obligation so later work cannot rely on a result the system never actually established.

State is the semantic starting point

Mechanism

Closed states and state-specific data

A record occupies a named state from a closed set. Data meaningful only in one state is constructible only in that state. Exhaustiveness checking makes new states visible to every caller that must interpret them.

Consequence

Readers stop decoding combinations

Meaning no longer depends on everyone interpreting flags, nulls, status strings, and related fields in exactly the same way.

Decision view

Only the relevant authoritative state is projected

The view must be semantically complete for the contract. If an omitted authoritative fact could change legality, evidence requirements, coverage, capability applicability, obligations, policy, or transition outcome, the view is incomplete.

Evidence and coverage are separate concepts

Evidence

What observation or fact supports the decision?

Evidence carries identity, source, observation time, basis, and typed content. Derived evidence must form a closed, acyclic dependency set with every referenced input present.

Coverage

How completely did the observation method cover a named scope?

Coverage is Complete, Partial, or Unknown for a contract/domain-defined scope. Partial and Unknown are distinct, and neither can be promoted to Complete because a provider was confident or a call succeeded.

Coverage is not itself Evidence. A coverage claim cites Evidence as provenance. A contract may require Complete coverage for selected scopes, while allowing other scopes to remain Partial or Unknown.

Evidence in depth →

Negative knowledge requires a complete search scope

"Not found" is not the same as "absent." Ordo keeps unavailable, not searched, not compared, unsupported, unknown, and absent separate. A negative observation can support absence only when the observation method could detect the target and the matching coverage scope is Complete.

Why this matters

Without scoped coverage, missing information can silently become a false fact. Ordo forces the system to say whether the thing is absent or whether the system simply failed to establish that it was present.

Legal transitions define the action space

Transitions

Change happens through named routes

Guards, invariants, policy, evidence requirements, capability requirements, and obligations determine whether the transition exists for the current state.

Capabilities

Authority is supplied, not invented

A Capability means the host has already established semantic authority needed for the action. It is not a credential and model output can never create one.

Obligations

Unresolved work can block the next transition

Obligations represent work the domain still requires. They remain part of the semantic state until satisfied rather than disappearing into operational notes.

External effects report what actually happened

Request

The semantic core requests the effect

Tier Two returns requested work as data. Tier Three coordinates it. Tier Four performs the database, network, browser, filesystem, provider, queue, clock, or other external work.

Interpretation

The domain interprets Succeeded, Failed, or Unknown

If an effect may have occurred but the result is unknown, Ordo does not collapse that into failure. It creates reconciliation work before later actions are allowed to depend on the uncertain result.

Retry before reconciliation is allowed only when the real external contract proves retry safety for that operation. Even then, reconciliation remains necessary before later work that requires knowing what actually occurred.

Boundary preservation in depth →

Four-tier architecture

Semantic responsibility stays separate from infrastructure.

Tier One

Semantic Model

What can be true: domain state, evidence, coverage, capabilities, obligations, uncertainty.

Tier Two

State Transition / Domain Execution

What legal change may happen: decisions, guards, policy, transitions, effects requested as data.

Tier Three

Application / Projection / Orchestration

Coordinates use cases and boundaries without becoming a second source of semantic truth.

Tier Four

Host / External Effects

Performs and observes infrastructure work, including explicit unknown outcomes.

The guardrail

Dependencies point toward the semantic core. Ordo may refine Tier One and Tier Two semantics, but it must never require the semantic core to import databases, HTTP, browser APIs, provider SDKs, persistence adapters, or ROS implementation dependencies.

Structural locality bounds the context needed for change

Mechanism

Route to semantic authority instead of exploring the repository

Semantic maps and feature ownership make state, transitions, contracts, effects, and tests deterministically discoverable. Navigation artifacts point to authority rather than restating it.

Consequence

The working context can stay bounded

Humans and agents can enter the feature through a small declared context and expand only when evidence shows the context is insufficient.

Verification is heterogeneous on purpose

Mechanical

Use the earliest trustworthy refusal

Type checks, architecture checks, structural checks, contract checks, and other mechanical mechanisms catch different classes of failure before broader behavioral review.

Behavioral

Test the domain behavior

Executable specifications and integration tests verify that allowed transitions and boundary behavior match the intended semantics.

Independent

Use a mechanism with different blind spots

Independent adversarial review matters because a green build and a passing test suite do not cover every failure class.

Engineering method

Ordo is also an order of work.

State-directed architecture is not enough if the engineer or agent works around the mechanisms that make it useful.
