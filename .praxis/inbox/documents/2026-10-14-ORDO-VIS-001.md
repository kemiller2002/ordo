## Original requirements and acceptance criteria from GitHub issue #92

## Problem
The Summa/Signal color investigation shows that adopting Forma does not ensure an agent selected an appropriate palette for a product. Design intent has not been an authoritative, reviewable input before coding. This is a *decision provenance* defect, not just a CSS defect.

## Requirements
- **ORDO-VIS-001.1:** Define a typed, versioned visual-intent decision in Ordo's requirement/Construction IR path for each user-facing application/surface. Record originating requirement IDs, owner, decision status (`approved`, `provisional`, `unknown`, `not-applicable`), selected Forma release/brand/theme/profile, task importance hierarchy, semantic color mappings, permitted exceptions, and rationale.
- **ORDO-VIS-001.2:** Preserve traceability from source requirements -> approved visual decision -> delegated work packages -> implementation verification. No requirements silently dropped in summarization or cohort formation.
- **ORDO-VIS-001.3:** Treat a missing or unsupported color/brand decision as an explicit unknown/obligation; never manufacture user approval or reinterpret an agent preference as an approved product choice.
- **ORDO-VIS-001.4:** Construction plans must constrain supported token roles and semantic mappings. Coding agents may request changes to the decision contract but may not silently invent new brand colors or tokens.
- **ORDO-VIS-001.5:** Make changes versioned and replayable, with stable schema and explicit approval evidence. Preserve capability for automated execution where valid policy already exists; do not block headless builds over purely cosmetic, not-applicable surfaces.

## Acceptance criteria
- Schema/validation round-trip tests cover approved, provisional, missing, contradictory, deprecated and not-applicable visual decisions.
- Fixture: Summa calls an unsupported `--ef-color-action-primary`; the plan flags it as unsupported/missing contract rather than treating its hex fallback as legitimate.
- Fixture: two applications share Forma but legitimately select different product theme profiles; both retain separate intent and provenance.
- Integration references current Ordo [ECIR #59](https://github.com/kemiller2002/ordo/issues/59), [construction operations #64](https://github.com/kemiller2002/ordo/issues/64) and product design-system authority, without introducing a parallel source of truth.

## Scope boundary
Ordo governs the decision and its traceability. Forma owns color contracts; Dokimos verifies code; Praxis enforces evidence gates.
